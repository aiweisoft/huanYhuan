# 缓一缓 · 需求规格（v0.1）

> 结论：首版是**单机版**匿名情绪树洞 + 心理科普内容库，先验证「说出来会不会舒服一点」，
> 不做真实社交网络、不做诊断、不做全网爬虫。
> 决策日期：2026-11-05

---

## 1. 要解决的问题

容易内耗的人并不缺信息，缺的是两个东西：

1. **一个不评判的出口**——发出去不会被比较、被评价、被追问「你怎么了」。
2. **能落地的解释**——不是「想开点」，而是「你现在这样，大概是因为什么，可以做什么」。

现有产品的问题：社交平台用点赞、粉丝、排行榜放大比较；心理类内容要么太学术，要么直接卖课卖咨询。

## 2. 目标用户

| 维度 | 描述 |
|---|---|
| 核心 | 20–40 岁，长期轻度焦虑/内耗，没有确诊，也不打算马上就医 |
| 场景 | 睡前、通勤、开完一个难受的会、和人起了冲突之后 |
| 诉求 | 把话写出来；读一点能解释自己的东西；不想暴露身份 |
| 顾虑 | 被熟人看到、被说矫情、被推销、被贴标签 |

## 3. 首版范围

**做**

- 匿名树洞：发一条情绪，只能收到「抱一下」和预设的善意回应
- 内容库：分类、搜索、收藏、已读、字号调节
- 危机干预：关键词触发求助卡片，内置 12356 等热线
- 本地数据：昵称、帖子、收藏全部存本机，可导出、可清空

**不做（明确排除）**

- 真实用户之间的社交（首版没有服务端，看不到别人的真实帖子）
- 评论楼中楼、私信、关注、话题广场
- 任何诊断、量表评分、用药建议
- 全网爬虫抓取（版权与合规风险）
- 付费、会员、广告

## 4. 功能需求

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-1 | 发树洞 | 选情绪标签 + 最多 500 字，匿名发布 | P0 |
| FR-2 | 浏览树洞 | 按情绪筛选，卡片展示，无热度排序 | P0 |
| FR-3 | 轻互动 | 「抱一下」；预设回应（我在/抱抱你/慢慢来…）+ 一句话 | P0 |
| FR-4 | 内容库 | 分类、搜索、阅读、收藏、已读标记 | P0 |
| FR-5 | 危机识别 | 命中自伤/自杀相关表达时展示求助卡片 | P0 |
| FR-6 | 我的 | 匿名昵称、我的帖子、收藏、统计（仅自己可见） | P1 |
| FR-7 | 数据管理 | 导出 JSON、清除示例、清空全部 | P1 |
| FR-8 | 内容导入 | 命令行抓取 RSS/Atom 生成文章数据 | P1 |
| FR-9 | 免责声明 | 关于页完整声明 + 文章底部提示 | P0 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 隐私 | 不采集手机号、位置、通讯录；无第三方统计 SDK；数据只在本机 |
| 合规 | 不做医疗建议；危机场景给出去处；上架前补隐私政策与用户协议 |
| 性能 | 列表首屏 < 1s；单页 DOM 不超过 500 节点；正文长文可滚动无卡顿 |
| 可用性 | 单手可操作；正文对比度 ≥ 4.5:1；关键按钮 ≥ 88rpx 高 |
| 可维护 | 页面/组件/数据分层；新增内容不改代码，只改 JSON/JS 数据文件 |

## 6. 验收标准

1. 新安装打开即有一条欢迎语气，不出现空屏。
2. 发一条帖子后返回列表，能立刻看到且标记「我写的」。
3. 同一条帖子只能抱一次，重复点击给出提示。
4. 搜索「失眠」能命中标题或正文包含该词的文章。
5. 收藏后「我的-收藏」与书签状态同步，取消后消失。
6. 正文输入「我不想活了」，出现求助卡片且热线可拨号。
7. 清除示例内容后，示例帖子消失、自己的帖子保留。
8. 清空全部数据后，昵称重新生成、列表为空、不自动回填示例。
9. 断网状态下所有功能可用（除拨号与打开原文链接）。
10. H5 与 App 端视觉一致，无横向滚动条。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 内容版权 | 只接开放 RSS 或自有内容，正文保留原文链接，不做全文转载站 |
| 医疗合规 | 全站免责声明；不做量表诊断；危机词触发干预 |
| 无人发帖（冷启动） | 首版单机不依赖网络效应；后续再引入真实社区 |
| 应用商店审核 | 心理类目需说明资质与审核机制，提前准备隐私政策 |
| 用户误解为「心理咨询」 | 名称与文案避免「治疗」「疗愈」承诺，统一用「科普」「记录」 |
