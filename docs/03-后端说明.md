# 缓一缓 · 后端说明（uniCloud 支付宝版）

> 对应版本：v0.2（云端化后的第一版）
> 服务空间：支付宝（`uniCloud-alipay`）
> 云对象：`huanhuan-co`；数据库：`huanhuan-posts` / `huanhuan-echoes` / `huanhuan-reports` / `huanhuan-articles`

---

## 1. 分层与总原则

```
App（uni-app）
  └─ common/api.js          统一入口，抛 { code, message }
       └─ uniCloud.importObject('huanhuan-co')
            └─ 云对象 huanhuan-co
                 ├─ huanhuan-posts    帖子
                 ├─ huanhuan-echoes   抱抱 / 文字回应
                 ├─ huanhuan-reports  举报
                 └─ uni-id            身份与角色（admin）
```

四条硬规则：

1. **所有读写都走云对象。** 三张业务表的 schema 权限全部是
   `read/create/update/delete: false`，客户端直连数据库一定失败。
2. **能匿名就匿名。** 发帖 / 列表 / 详情 / 我的，都接受本机 `anonId`；
   只有「抱一下 / 留一句 / 举报」要求登录。
3. **身份不外泄。** `user_id`、`anon_id` 只落库，云对象返回给客户端的对象里没有这两个字段。
4. **schema 校验对云对象不生效。** 云对象用的是管理端权限，长度、敏感词、
   频率限制必须在云对象里自己做——这是本文件第 5 节的全部内容。

## 2. 集合与字段

### 2.1 `huanhuan-posts`

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 系统生成 |
| `mood` | string | `anxious` / `low` / `sleep` / `friction` / `social` / `tired` |
| `text` | string | 正文，≤ 500 字，前后 trim |
| `user_id` | string | 登录用户 id；匿名为空串 |
| `anon_id` | string | 本机匿名标识，`^[A-Za-z0-9_-]{8,64}$` |
| `at` | timestamp | 创建时间 |
| `status` | string | `published` / `reviewing` / `hidden` |
| `hug_count` | int | 抱抱数，`inc(1)` 累加 |
| `echo_count` | int | 文字回应数 |
| `report_count` | int | 举报次数，满 3 转 `reviewing` |
| `risk` | bool | 命中危机词。**只做标记，不阻断发布** |
| `moderated_by` | string | 最后操作的管理员 uid（仅后台） |
| `moderated_at` | timestamp | 最后审核时间 |

索引：

| 索引 | 字段 | 用途 |
|---|---|---|
| `status_at` | `status` ↑, `at` ↓ | 首页列表、审核队列 |
| `user_id_at` | `user_id` ↑, `at` ↓ | 我的帖子（登录用户） |

> `anon_id` 目前没有单独索引。数据量上来后如果「我的」变慢，再加
> `anon_id_at`。现在的量级不值得占索引。

### 2.2 `huanhuan-echoes`

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | **抱抱用固定 id：`postId + '_' + uid`** |
| `post_id` | string | 帖子 id |
| `user_id` | string | 操作者 |
| `kind` | string | `hug` / `word` |
| `text` | string | 仅 `word` 使用，≤ 40 字 |
| `at` | timestamp | 时间 |

索引：

| 索引 | 字段 | 说明 |
|---|---|---|
| `post_id_at` | `post_id` ↑, `at` ↑ | 详情页回声按时间正序 |
| `post_user_kind` | `post_id` ↑, `user_id` ↑, `kind` ↑ | 查询「我抱过没有」；**非唯一索引** |

**为什么抱抱要固定 `_id`？**
`post_user_kind` 不是唯一索引，靠「先 count 再 add」在并发下会写进两条，
`hug_count` 就多加了一次。改成固定主键后：

- 第一次写成功 → 计数 +1；
- 第二次写入直接触发主键冲突（`E11000` / duplicate）→ 捕获后返回
  `{ ok: false, message: '已经抱过啦' }`，计数不变。

整个过程只有一次写，没有「查—判断—写」的竞态窗口。

### 2.3 `huanhuan-reports`

| 字段 | 类型 | 说明 |
|---|---|---|
| `post_id` | string | 被举报的帖子 |
| `user_id` | string | 举报人（去重用） |
| `reason` | string | 中文原因：广告或引流 / 伤害性内容 / 辱骂或攻击 / 其他 |
| `at` | timestamp | 时间 |

同一用户对同一帖只能举报一次（云对象里先 `count` 再写）。
举报成功后 `posts.report_count + 1`，累计到 3 且当前是 `published` 时自动转 `reviewing`。

### 2.4 `huanhuan-articles`

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 内置文章沿用原 id（如 `a-understand-rumination`），新建自动生成 |
| `title` | string | 标题，≤ 100 字 |
| `category` | string | 分类，如「认识情绪」 |
| `source` | string | 来源，默认「编辑部」 |
| `summary` | string | 列表摘要，≤ 200 字 |
| `body` | array | 正文段落，字符串数组 |
| `url` | string | 原文链接，可空 |
| `minutes` | int | 预计阅读分钟数 |
| `status` | string | `published` / `draft` / `hidden` |
| `sort` | int | 排序权重，大的在前 |
| `at` | timestamp | 发布时间 |
| `created_at` / `updated_at` | timestamp | 创建 / 更新时间 |
| `created_by` / `updated_by` | string | 操作的管理员 uid |

索引：`status_sort`（`status` ↑ `sort` ↓ `at` ↓）、`category_status`。

客户端行为：

- `common/articles.js` 先读本地缓存，没有再读内置文章，然后后台静默刷新云端
- 云端返回空（还没导入）时保留内置 12 篇，不会把「读一点」刷成空白
- 后台点一次「导入内置文章」，这 12 篇就会写进云端，之后以云端为准

## 3. 状态机

```
            createPost（命中敏感词）
                    │
                    ▼
   published ────────────────► reviewing ──────► hidden
      ▲  ▲                        │  │             ▲
      │  └── adminModerate        │  └─ adminModerate(hide)
      │      (publish)           │        deletePost（作者）
      │                          │
      └──────────────────────────┘
          adminModerate(publish)：report_count 归零
```

| 状态 | 列表可见 | 详情可见 | 能抱 / 能回应 |
|---|---|---|---|
| `published` | ✅ | ✅ | ✅ |
| `reviewing` | ❌ | 仅作者本人 | ❌ |
| `hidden` | ❌ | ❌（返回 `HUAN_NOT_FOUND`） | ❌ |

要点：

- **命中敏感词不是拒绝，是转人工。** 宁可多发一条给管理员看，也不要把
  情绪表达卡在发布按钮上。
- **删除是软删。** `deletePost` 只把 `status` 改成 `hidden`，数据保留，
  便于事后追溯（也便于误删恢复，后期可做）。
- **放行会清零 `report_count`。** 否则一条被误举报的帖子只要再来 1 次举报
  就会重新进审核。

## 4. 云对象方法表

统一约定：成功返回数据对象；失败 `throw` 带 `errCode` 的 Error，
客户端在 `common/api.js` 里归一化成 `{ code, message }`。

### 4.1 用户侧

| 方法 | 参数 | 登录 | 说明 |
|---|---|---|---|
| `listPosts` | `mood?`, `cursor?`, `limit?`, `anonId?` | 可选 | 首页分页，只出 `published`，返回 `hugged` / `isMine` |
| `getPost` | `id`, `anonId?` | 可选 | 详情 + 最近 100 条文字回声；`reviewing` 只有作者能看 |
| `createPost` | `mood`, `text`, `anonId?` | 可选 | 匿名也可发；60 秒 1 条；命中敏感词 → `reviewing` |
| `hug` | `postId` | **必须** | 固定 `_id` 幂等；重复抱返回原计数 |
| `echo` | `postId`, `text` | **必须** | ≤ 40 字；同帖 20 秒 1 条 |
| `reportPost` | `postId`, `reason` | **必须** | 一人一帖一次；满 3 次转审核 |
| `deletePost` | `postId`, `anonId?` | 可选 | 作者本人（登录或同 `anonId`）软删 |
| `myPosts` | `cursor?`, `limit?`, `anonId?` | 可选 | 登录 id 与本机 id 的并集 |
| `myStats` | `anonId?` | 可选 | 帖子数 + 收到的抱抱总数 |
| `listArticles` | `category?`, `skip?`, `limit?` | 否 | 已发布文章，按 `sort` / `at` 倒序；列表不返回 `body` |
| `getArticle` | `id` | 可选 | 文章详情；非 `published` 仅管理员可读 |

### 4.2 管理侧（需 `admin` 角色）

| 方法 | 参数 | 说明 |
|---|---|---|
| `adminListQueue` | `status?`, `mood?`, `skip?`, `limit?` | 按状态分页取帖子，默认 `reviewing`；带 `reportCount` / `risk` / `moderatedAt` |
| `adminModerate` | `postId`, `action` | `publish` / `hide` / `review`，写入 `moderated_by` 与 `moderated_at` |
| `adminListReports` | `postId?`, `skip?`, `limit?` | 举报流水，带举报人 uid，按时间倒序 |
| `adminGetPost` | `postId` | 单条详情，含回应与举报记录，可见 `hidden` |
| `adminListArticles` | `status?`, `skip?`, `limit?` | 文章列表（含草稿/下架） |
| `adminGetArticle` | `id` | 文章全文，编辑用 |
| `adminSaveArticle` | `id?`, `title`, `category`, `summary`, `body[]`, `status`, `sort`, … | 新建或更新 |
| `adminSetArticleStatus` | `id`, `status` | 快速发布 / 下架 |
| `adminDeleteArticle` | `id` | 物理删除 |
| `adminSeedArticles` | `articles[]` | 导入内置文章，同 id 跳过 |

角色判断：`checkToken` 的 payload 里 `role` 是数组，`role.includes('admin')`。
在 HBuilderX → uniCloud → 用户管理里给管理员账号加 `admin` 角色即可。

## 5. 内容安全（全部在云对象内）

| 维度 | 规则 | 位置 |
|---|---|---|
| 长度 | 帖子 ≤ 500；回声 ≤ 40；`text` 前后 trim | `createPost` / `echo` |
| 空白 | 只有空白的文本直接拒绝 | 同上 |
| 引流词 | `BLOCKED_WORDS` 命中 → 帖子转 `reviewing`，回声直接拒 | `containsBlocked` |
| 危机词 | `CRISIS_PATTERNS` 命中 → 只写 `risk: true`，**不拦** | `detectCrisis` |
| 发帖频率 | 同一身份 60 秒 1 条（登录看 `user_id`，匿名看 `anon_id`） | `createPost` |
| 回声频率 | 同一人对同一帖 20 秒 1 条 | `echo` |
| 举报 | 一人一帖一次；3 次自动进审核 | `reportPost` |
| 身份 | `anon_id` 必须匹配 `^[A-Za-z0-9_-]{8,64}$` | `normalizeAnonId` |

危机词只标记不拦截是产品决策：拦截会把人推走，给出口比堵住更有用。
客户端 `common/crisis.js` 负责在输入时弹出求助卡片，后端 `risk` 只用于
后台排查与统计。

### 已知不足

- 引流词是纯 `includes` 匹配，绕过方式很多（拆字、拼音、谐音）。
  真正的防线是「举报 + 人工审核」，词表只是第一层筛子。
- 没有接入第三方内容安全 API（支付宝空间可接内容安全服务），
  上线前建议补一道图片/文本机审。
- 频率限制是「查最近 60 秒有没有」，不是分布式令牌桶；单条帖子并发
  提交仍可能过 1~2 条，属可接受范围。

## 6. 客户端约定（`common/api.js`）

- 每次调用自动带上 `anonId`（来自 `common/store.js` 的 `getAnonId()`）。
- 错误归一化：
  - `HUAN_LOGIN_REQUIRED` / `uni-id-token-expired` / `uni-id-check-token-failed`
    / `uni-id-permission-error` → `code: 'NEED_LOGIN'`
  - 无 `errCode` 且文案像网络错误 → `code: 'NETWORK'`
  - 其余原样透传 `errCode`
- 页面拿到 `NEED_LOGIN` 时调用 `goLogin()` 跳 uni-id 登录页；
  拿到 `NETWORK` 时按离线处理，不弹错误弹窗。

错误码清单：

| errCode | 含义 |
|---|---|
| `HUAN_LOGIN_REQUIRED` | 未登录 |
| `HUAN_FORBIDDEN` | 无权限（非作者 / 非管理员） |
| `HUAN_NOT_FOUND` | 不存在或已下架 |
| `HUAN_EMPTY` | 内容为空 |
| `HUAN_TOO_LONG` | 超长 |
| `HUAN_INVALID_MOOD` | 情绪标签非法 |
| `HUAN_INVALID_ACTION` | 审核动作非法 |
| `HUAN_BLOCKED` | 命中引流词 |
| `HUAN_TOO_FREQUENT` | 触发频率限制 |

## 7. 部署清单

在 HBuilderX 里，对 **App 工程 `huanYhuan`** 操作：

1. 右键 `uniCloud-alipay/database` → **上传所有 DB Schema**
   （含 `huanhuan-articles`，以及 `huanhuan-posts.index.json` / `huanhuan-echoes.index.json`，索引会一起建）
2. 右键 `uniCloud-alipay/cloudfunctions/huanhuan-co` → **上传部署**
3. 确认工程已关联支付宝服务空间（右键项目 → uniCloud → 关联云服务空间）

文章（可选，第一次）：

4. 登录管理后台 `huanYhuanWeb` → 「缓一缓 → 文章管理」→ 点 **导入内置文章**，把 12 篇写进云端

账号侧：

5. 在 uniCloud 控制台 → uni-id 用户管理，给自己账号加 `admin` 角色
6. 用该账号登录后台 `huanYhuanWeb`，进入「缓一缓」三个菜单验证权限

自测三条：

- 发一条 → `huanhuan-posts` 多一行，`status = published`
- 抱一下 → `hug_count +1`，`huanhuan-echoes` 多一条 `_id = postId_uid`
- 再抱一次 → 提示「已经抱过啦」，`hug_count` 不变
