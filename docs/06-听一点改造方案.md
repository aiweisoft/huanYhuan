# 听一点改造方案（v0.6）

> 依据：`my-music/AGENTS.md` 第 5 章「音频播放实现要点」 + `utils/content-uri.js` / `utils/file-picker.js` / `utils/audio-manager.js` 的实现。
> 结论：我们之前的写法触犯了对方文档里明确列出的三条铁律，这是「加进去也播不了 / 重启就失效」的根因。

## 1. 之前错在哪

| 我们的写法 | 问题 | my-music 的做法 |
|---|---|---|
| `new File(cacheDir, name)`、`new FileOutputStream(file对象)` | 5+ 运行时对「桥接对象当构造参数」不可靠，**静默抛异常被 catch 吞掉** | 全程字符串路径：`new File(dirPath)`、`new FileOutputStream(dirPath + name)` |
| `plus.android.invoke(Uri, 'parse', ...)` | 静态方法这么调不生效 | `Uri.parse(str)` |
| 先解析成共享存储原路径，直接存下来播 | 原路径依赖 SAF 的**进程级**授权，杀进程后失效 | 导入时一律复制到应用私有目录，`path` 只指向副本 |
| 复制到 `getCacheDir()` | 系统会清理，歌单会一夜全失效 | 复制到 `_doc/audio/`（应用私有文档目录） |
| 失败空 `catch` | 用户只看到「播不了」，无从判断 | 记录 `getLastCopyError()` 并弹窗告知 |

## 2. 目标

- 听一点**只播本机音频**，自带音频全部移除（已移除 `static/audio/`，APK 也因此小了一半）
- 导入即复制到 `_doc/audio/`，播放只认副本；杀进程重进仍能播
- 导入失败要告诉用户原因，不允许静默跳过
- 文件被删/副本丢失时，列表显示「文件已失效」，不把无效路径交给播放器

## 3. 结构

```
common/
├── content-uri.js   # 移植 my-music：ensureLocalCopy / resolveContentUriPath / 副本清理
├── file-picker.js   # 移植 my-music：ACTION_OPEN_DOCUMENT + 持久授权 + 导入即复制 + 读 ID3
├── listen.js        # 只做本机音频的 CRUD（存储 key 不变：huanhuan.localTracks.v1）
└── player.js        # 单例播放器：每曲重建 InnerAudioContext，只播 track.path
pages/listen/listen.vue  # 只列本机音频：导入 / 播放 / 失效提示 / 移出
```

数据模型（本地音频）：

```js
{
  id, title, author, duration,
  uri:  'content://...',        // 原始 URI，副本丢失时可重新复制
  path: '.../doc/audio/xxx.mp3',// 应用私有副本，长期可用（H5 为临时路径）
  broken: false                 // 运行时标记：副本不存在
}
```

## 4. 播放器规则（照抄 my-music）

1. 全局单例，页面只调公开 API，不自己 `createInnerAudioContext`
2. **每首重建实例**：`destroy()` 旧的再建新的（避免 -99 / 事件串台）
3. `sessionCategory = 'playback'`
4. 赋 `src` 前后都保证能起播：`autoplay = true` + `onCanplay` 里补一次 `play()`
5. 播放前用 `localFileExists(path)` 校验；文件不存在就标 `broken` 并跳过，不硬播
6. `onError` 只弹一次提示，避免每次点都报
7. 进度：`onTimeUpdate` 事件 + 页面 500ms 轮询双保险（App 端事件偶发丢失）

## 5. 导入流程

1. 原生 `Intent.ACTION_OPEN_DOCUMENT` + `FLAG_GRANT_READ_URI_PERMISSION` + `FLAG_GRANT_PERSISTABLE_URI_PERMISSION`
2. 拿到结果立刻 `takePersistableUriPermission()`
3. `ensureLocalCopy(uri)`：复制到 `_doc/audio/`，按 URI 哈希命名（防同名覆盖）
4. 复制成功才入库；失败跳过并记录原因
5. 读 `MediaMetadataRetriever` 取标题/时长，读不到用文件名兜底
6. 结果：成功 N 首 / 失败 M 首 + 原因，用 `uni.showModal` 明确告知

## 6. 兼容与清理

- 老数据只有 `file` 字段：迁移成 `path`，`uri` 留空；文件不存在则标 `broken`
- 移出音频时：`deleteManagedCopy(path)` 只删我们自己复制出来的副本，外部文件不动
- H5 端：`uni.chooseFile` 的路径是临时 blob，刷新后会失效，仅用于调试

## 7. 验证

1. `publish h5`（覆盖普通分支）与 `publish app --type appResource`（覆盖 `#ifdef APP-PLUS` 分支）都编译一遍
2. H5：塞一个本地 mp3 条目，点播放看进度条、暂停、切歌
3. App：导入一首 → 播 → 杀进程重进再播（关键用例）
4. 有设备连 adb 时：`ls -l /sdcard/Android/data/<包名>/apps/__UNI__8927398/doc/audio/` 确认副本落盘，`logcat | grep content-uri`

## 8. 风险

- 导入会在手机里存两份（原文件 + 副本），这是用空间换「重启后一定能播」
- 个别 ROM 对应用私有目录有限制；失败会明确提示，不再静默
