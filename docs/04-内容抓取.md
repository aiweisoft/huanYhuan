# 抓取「读一点」内容（RSS）

工具：`tools/rss-import.mjs`（零依赖，Node 18+）
目标：把外部源抓成结构化文章 → 人工筛 → 后台「批量导入」写进云端。

> 想直接看跑通的样子，跳到最后一节「10. 完整实例」，那里有一次真实抓取的命令和结果。

## 1. 准备源

编辑 `tools/feeds.json`：

```json
[
  "https://example.com/feed.xml",
  { "url": "https://rsshub.app/zhihu/people/activities/xxx", "name": "知乎专栏" }
]
```

- 字符串或 `{ url, name }` 都行
- `name` 会作为文章的 `source` 显示；不填就用域名
- 也可以不写文件，直接把 URL 跟在命令后面
- 想另起一份清单（比如留一份能跑通的示例），加 `--feeds`：

```powershell
node tools\rss-import.mjs --feeds tools\feeds.example.json
```

## 2. 先试抓（不写文件）

```powershell
cd D:\Users\Administrator\Documents\HBuilderProjects\huanYhuan

node tools\rss-import.mjs --dry --limit 5 https://www.example.com/feed.xml
```

`--dry` 只打印标题和链接，确认源对不对、内容是不是你要的。

遇到 403 时换一个浏览器 UA：

```powershell
node tools\rss-import.mjs --dry --ua "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120 Safari/537.36" https://www.example.com/feed.xml
```

## 3. 正式抓取

```powershell
# 读 feeds.json，每个源最多 10 条
node tools\rss-import.mjs --limit 10

# 或者只抓一个源
node tools\rss-import.mjs --limit 10 https://www.example.com/feed.xml

# 输出到单独文件，不覆盖默认文件
node tools\rss-import.mjs --limit 10 --out tools\batch-2026-11.js

# 要纯 JSON（后台也能识别，和 docs\import 里的文件格式一致）
node tools\rss-import.mjs --limit 10 --json --out docs\import\batch.json
```

默认输出：`common/data/articles.generated.js`（会覆盖）。
**没抓到内容时不会覆盖原文件**，放心重试。

每条文章的结构：

```json
{
  "id": "rss-xxxx",
  "title": "标题",
  "category": "外部导入",
  "source": "源名称或域名",
  "summary": "第一段摘要",
  "body": ["第一段", "第二段"],
  "url": "原文链接",
  "minutes": 3,
  "sample": false
}
```

`minutes` 是脚本估的：中文按约 150 字/分、英文按约 200 词/分，向上取整，和内置文章的口径一致；英文源常常只给摘要，所以数字会偏小，改写时按实际长度调一下。

## 4. 人工筛一遍

抓完不要直接发，至少看这几项：

- 营销号、标题党、带诊断结论、荐药的内容 → 删除
- `body` 只有一两句的（很多源只给摘要）→ 要么补全，要么只当导流
- `url` 是否能打开、是否需要登录
- 分类是否要改（脚本统一给「外部导入」，可在后台编辑）

## 5. 导入云端

1. 打开输出文件，全选复制
2. 后台 `huanYhuanWeb` →「缓一缓 → 文章管理」→「批量导入」
3. 粘贴 → 看识别条数
4. 勾选「导入后直接发布」或留草稿（不勾选一律存草稿，JSON 里的 `status` 不会覆盖这个选择）
5. 点「导入」

同 `id` 会跳过，重复导入不会产生重复文章（前提是源带稳定 link/id）。
草稿只存在于后台，App 的「读一点」只展示已发布文章；确认没问题后在后台点「发布」。

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `HTTP 403 / 401` | 反爬。换 UA；或改用 RSSHub；或换源 |
| `请求超时（15 秒）` | 网络问题；检查代理/VPN；换源 |
| `抓到 0 条` | 不是标准 RSS/Atom；或页面是 JS 渲染，需要 RSSHub |
| 标题正常、正文只有一句 | 源只提供 summary；这类内容更适合做「导读 + 原文链接」 |
| 中文乱码 | 源是 GBK 编码，Node 默认按 UTF-8 解码；用 RSSHub 中转或先转码 |
| 公共 RSSHub 限流 | 自建 RSSHub，或换可用实例 |

## 7. 源从哪里找

- 网站页脚 / 头部找 RSS 图标，常见路径：`/feed`、`/rss.xml`、`/atom.xml`、`/index.xml`
- **RSSHub**：给没有 RSS 的站点生成订阅（公众号、知乎、豆瓣、微博、B 站等）
  公共实例经常限流，长期用建议自建
- **开放获取**：PubMed 检索式 RSS、Frontiers / BMC / PLOS 等 CC BY 期刊
- **机构科普**：WHO、国家卫健委「健康中国」等，多数没有 RSS，需要手动录入
- **公众号**：wechat2rss / RSSHub，**版权仍归作者**，先拿授权，只做摘要 + 原文链接

## 8. 版权与质量红线

- 不全文搬运；保留作者、来源、原文链接
- 商业使用需要授权；拿不准就不用
- 不发布诊断结论、用药建议、夸大疗效的内容
- 危机内容要配求助卡片（前端已有，正文命中危机词会自动出现）

## 10. 完整实例（2026-11-08 实跑）

这是一次真实抓取，命令、输出、坑都记下来，照抄即可复现。

### 10.1 源清单

新建 `tools/feeds.example.json`（不动你自己的 `tools/feeds.json`）：

```json
[
	{ "url": "https://www.sciencedaily.com/rss/mind_brain.xml", "name": "ScienceDaily · 心智与大脑" },
	{ "url": "https://greatergood.berkeley.edu/rss", "name": "Greater Good（UC Berkeley）" }
]
```

两个源都验证过可直连、有近期更新：

| 源 | 内容 | 特点 |
|---|---|---|
| ScienceDaily · Mind & Brain | 脑科学 / 心理研究新闻 | 更新频繁，每条只有一段摘要（约 300 词以内） |
| Greater Good（UC Berkeley） | 幸福感、共情、亲社会 | 部分文章带全文，部分只有一句导语 |

### 10.2 先试抓

```powershell
cd D:\Users\Administrator\Documents\HBuilderProjects\huanYhuan
node tools\rss-import.mjs --feeds tools\feeds.example.json --dry --limit 3
```

输出（节选）：

```
抓到 3 条：ScienceDaily · 心智与大脑
抓到 3 条：Greater Good（UC Berkeley）

【dry-run】共 6 条，未写入文件：
1. [外部导入] Drinking 2–3 cups of coffee a day linked to dramatically lower dementia risk  https://www.sciencedaily.com/releases/2026/11/261105224550.htm
...
```

`--dry` 不写文件，先确认标题和链接是不是你要的方向。

### 10.3 正式抓取（原样存档）

```powershell
node tools\rss-import.mjs --feeds tools\feeds.example.json --limit 5 --json --out docs\import\2026-11-08-rss-raw.json
```

输出：

```
抓到 5 条：ScienceDaily · 心智与大脑
抓到 5 条：Greater Good（UC Berkeley）
共写入 10 条到 docs\import\2026-11-08-rss-raw.json
```

结果文件：`docs/import/2026-11-08-rss-raw.json`（10 条英文原文，纯 JSON）。

`--json` 是这次新加的选项：不加它就是默认的 `export default [...]`（`articles.generated.js` 用的格式）；两种后台都能识别。

### 10.4 人工筛 + 改写成中文

| 抓到的 10 条 | 处理 | 原因 |
|---|---|---|
| 咖啡与痴呆风险 | ✅ 改写 | 有摘要、有原文链接，适合做研究速览 |
| 裸盖菇素重塑脑连接 | ✅ 改写 | 和压力机制相关，加足风险提示后可用 |
| 阅读能力与智力 | ✅ 改写 | 轻量、无医疗风险 |
| 雷帕霉素与阿尔茨海默 | ❌ 丢弃 | 涉及处方药和「预防」暗示，踩第 8 节的用药建议红线 |
| 左右脑交叉接线 | ❌ 丢弃 | 纯演化假说，和「缓一缓」的主题无关 |
| Greater Good 5 条 | ⏸ 暂缓 | 英文长文，要翻译压缩；其中 1 条只有一句导语 |

改写不是翻译全文：保留研究结论、去掉细节和术语，加上「相关不等于因果」「不构成医疗建议」这类必要的限定，原文链接和来源一律保留。

### 10.5 改写后的成品

文件：`docs/import/2026-11-08-rss-demo.json`（3 篇，可直接粘到后台）

| 标题 | 分类 | 段数 |
|---|---|---|
| 每天两三杯咖啡，和更低的痴呆风险有关 | 自我关照 | 5 |
| 压力损伤的脑回路，能被重新接上吗 | 认识情绪 | 5 |
| 孩子读得好不好，智力其实不是关键 | 自我关照 | 5 |

`status` 设成了 `draft`，导入后只会进草稿箱；要上线就在后台「发布」，或者导入时勾「导入后直接发布」。App 的「读一点」只展示已发布文章，草稿不会出现。

### 10.6 这次踩到的坑

- `tools/feeds.json` 里原来是 `https://www.zhihu.com/feed.xml`，知乎没有公开 RSS，实测 404。所以实例用 `--feeds` 单独指定清单，没改你的文件。
- 公共 RSSHub 实例（`rsshub.app`、`rsshub.rssforever.com`、`rsshub.feeded.xyz`）实测分别 `fetch failed` / `503` / `fetch failed`。想要知乎、公众号这类源，得自建 RSSHub。
- `verywellmind.com`、`mind.org.uk` 返回 403；`guokr.com/rss`、`xinli001.com/rss`、`jiandanxinli.com/feed` 都是 404。
- WHO 的 news RSS 能抓，但内容停在 2020 年，不适合当日常源。
- Greater Good 的部分条目没有 `pubDate`，`at` 会退化成抓取时间（这次 5 条里全部落在同一两毫秒内），排序时注意。

### 10.7 复用到自己的源

1. 把 `feeds.example.json` 换成你要的源，或直接改 `tools/feeds.json`
2. `--dry` 确认
3. 正式抓到 `--out docs\import\日期-raw.json`
4. 人工筛 + 改写成 `docs\import\日期-articles.json`
5. 后台「文章管理 → 批量导入」
6. 上线前过一遍第 8 节的版权与质量红线

## 11. 邮件投稿（半自动）

看到好内容时，不用开电脑，直接发邮件到 **sxzhizhi@163.com**。

### 怎么跑

1. 只处理发件人 `dyp_2001@163.com`，其他邮件一律忽略
2. 本机 Windows 计划任务 `邮箱总管` 每 10 分钟执行一次，一个任务按顺序做三件事：
   - `tools/mail-inbox.py`：收内容投稿，落到 `docs/import/inbox/`
   - `E:\ai-content-ops\tools\邮件指令.py`：处理知智快报的「做/发第 N 条」
   - `tools/process-huanhuan.py`：把主题为「缓一缓」的投稿改写并导入草稿
3. 提取正文（或链接页面）、附件（txt / docx / pdf）
4. 生成 `docs/import/inbox/mail-xxxx.json`，状态一律 `draft`
5. 需要我改写 + 导入时，说一句「处理 inbox」

### 支持什么

| 形式 | 说明 |
|---|---|
| 纯文字正文 | 最稳，按空行分段 |
| 普通文章链接 | 服务端抓取，标题取页面 `<title>` |
| txt / docx / pdf 附件 | 自动提取文字 |
| 图片附件 | 不做 OCR，会留一个 `_skip-xxxx.md` 说明 |

知乎、公众号这类反爬站点抓不到正文，直接把文字粘在邮件里，或发附件。

### 去重与日志

- 按 `Message-ID` 记录在 `tools/.mail-import-state.json`，同一封不会重复导入
- 运行日志：`tools/mail-import.log`
- 暂停/恢复任务：

```powershell
schtasks /Change /TN "邮箱总管" /DISABLE
schtasks /Change /TN "邮箱总管" /ENABLE
```

### 注意

- 这一步只负责「收集 + 提取」，不改写、不发布
- 导入后仍然是草稿，需要人工过一遍再点发布
- 版权边界同第 8 节：摘要 + 来源 + 原文链接，不全文搬运
